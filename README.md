## 线路和延迟：两份测评的结论不一样，都列出来

2026 年 5 月的一份第三方测评（测的正是 512MB 那款）给出的数据：

- 本地 ping 平均约 115ms，测试期间没有明显丢包
- 国内三网平均：**电信 78ms、联通 88ms、移动 86ms**，港澳台及东南亚 52ms，全 ISP 均值 83ms
- 路由走向：电信从广州出口直连东京，走电信骨干；联通从北京出口直连东京，走 AS4837；移动从上海出口经香港中转，走 CMI 到东京
- 全球节点稳定性整体不错，联通和移动丢包相对更低，部分电信节点略不稳定

2026 年 3 月另一份测评的结论有出入：回程电信和移动表现好，联通延迟偏高，而在高峰期测试里**电信反而是三网中最差的**。

两份数据不冲突，只是测的时间和机器不同。可以做参考的是：三网都在 80–90ms 这个区间，属于东京机房的正常水平，没有哪一家特别突出；晚高峰的波动比平均延迟更值得关注，如果你对稳定性要求高，尽量避开电信单线，或者自己准备备用线路。

## 哪些人不该买

直说几类不适配的情况，省得买完再退：

**需要 Windows 的**。日本套餐的测评明确写只支持 Linux，官方 FAQ 也否定了 Windows。另有中文汇总页称采用 KVM 架构“支持 Linux 和 Windows”，这条与专门评测冲突，如果你确实要 Windows，付款前找客服书面确认，别默认能用。

**需要高内存、高 CPU 的**。全系最高 768MB 内存、2 核，跑 Docker 多容器、数据库、编译环境都吃力。测评里的性能跑分本身也偏弱，FIO 读写有明显限制。

**需要多档配置弹性的**。日本节点就这三个固定配置，没有中间档，也不能单独加内存或硬盘。

**只想便宜建站、不在乎 IP 原生性的**。原生 IP 是溢价来源，你用不上就不该为它付钱。

**IP 真的是日本原生吗？**

日本套餐以 Linux 为主，官方 FAQ 明确说不支持 Windows。有中文资料称支持，属于冲突信息，下单前向客服确认。
